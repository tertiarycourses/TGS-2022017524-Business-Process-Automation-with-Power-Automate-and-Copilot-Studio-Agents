# Editorial Review — teaching notes (trainer only, not packaged)

**The plant-a-defect demo is the whole lab in one move.** Change a fee by $50 in a draft and send
it through. A reviewer that catches it proves the pipeline adds something; a reviewer that waves
it through proves the deeper point — that a checklist in a prompt is followed, not enforced. Both
outcomes teach. Run it live rather than promising it works.

**Why the verdict vocabulary is constrained.** "Recommend approval" vs "approved" looks like
pedantry until you connect it to Module 2's human-in/on/out-of-the-loop table: an agent whose
output is worded as a decision drifts into being treated as the decision-maker. The "For the
human" line exists for the same reason — it keeps the person reading the draft, not just the
verdict.

**The missing-brief refusal matters.** Learners will paste a draft alone; the agent must refuse
(it is in the instructions, not the skill — discuss why: the rule must hold even when the review
skill does not fire). A reviewer that will review against nothing is a rubber stamp with extra
steps.

**Sequencing note.** The stop-and-fail ordering (facts before voice) is a cost decision: a draft
failing check 1 is going back regardless, so style findings on it are wasted work — and, worse,
they let a "9 small fixes, 1 fee error" report bury the one finding that matters. Reviewers that
list everything equally train writers to skim reports.
